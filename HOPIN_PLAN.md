# Hopin build plan (real data only)

## Ground rules (agreed 2026-10-07; re-read before every step)

1. **Nothing simulated.** No simulated payments, fake references, demo buttons, fake seed data or "Simulate driving". If a feature is missing its key, the API says plainly that it isn't configured, and the UI shows that. It never pretends.
2. **No fake text in the app** to make something look finished.
3. **One step at a time.** Each step is: build → test against the real service → report what was verified → wait for your go-ahead.
4. **Keys are requested before the step that needs them.** You create the accounts; I never create accounts for you.
5. **Backend, database and APIs first.** You redesign the frontend afterwards.
6. **Costs are stated before a paid provider is used.** Prices change, so I check the provider's current pricing page at that step rather than quoting from memory.

## Do we need datasets?

**No Kaggle data is needed, and adding any would go against rule 1.** A ride app's data is its own users, trips and payments. Those come from real people using the app, not from a download. The external data the app uses is already real, and it is queried live, not copied in:

- **Roads, places and addresses:** OpenStreetMap, or whichever map provider we choose in step 11.
- **Routes, distances and travel times:** the routing service.

The one place a dataset could help is calibrating fares against real Indian fares. That is optional, and fares are business settings you choose anyway.
